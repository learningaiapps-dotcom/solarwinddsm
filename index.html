Solar forecast correction

Upload past forecast and actual generation (96 blocks per day). After loading a file you choose the day to correct. The days before it are the history used to learn the error.

Weather forecast loaded from the Weather data tab

Forecast MW = plant capacity × GHI ÷ 1000 × performance ratio. Enter the plant capacity below first. Actual file columns: date, block, actual_mw, event (optional), available_mw (optional). Without actual data the correction has nothing to learn from.

CSV columns: date, block (1-96), forecast_mw, actual_mw, event (blank, curtailment, outage, maintenance or meter_fail), available_mw. Leave actual_mw blank for the day to correct. Using Excel? Save as CSV first.

How is my file handled? (including a full year of data)

• Your file is read inside your browser. Nothing is uploaded or stored on any server.

• A full year is fine: 365 days × 96 blocks = 35,040 rows, processed in about a second. Several years also work.

• After you choose the file, a File check report shows rows read, days found, skipped rows, duplicates, missing blocks and tagged events.

• Pick the day to correct. It is corrected using only the days before it, never later days.

• Only the most recent days (the history window) feed each day's correction. Older days still count in the accuracy results and the accuracy-over-time chart.

• Dates must be YYYY-MM-DD (Excel often changes this). Block 1 = 00:00-00:15 plant time. If two rows share a date and block, the last one is used. Rows with an invalid block or forecast are skipped and counted.

Error factor for each of the 96 blocks. Every block has its own value, because forecasts miss differently at different times of day. Above 0 = forecast was usually too low in recent days.

Forecast versus actual, block by block. Bars show actual minus forecast (blue = original forecast, orange = corrected forecast). Shorter bars mean a better forecast.

Accuracy over time. Average daily miss (MAE) on each earlier day. The corrected line should sit below the original.

Wind forecast correction

Calculates a physics-based wind baseline from forecast wind speed and your turbine data, learns recent errors, and gives probable generation for the day you choose.

Weather forecast loaded from the Weather data tab

Wind speed at 80 m is used as the hub-height speed (air density 1.225 kg/m³). Fill in your turbine details below. Actual file columns: date, block, actual_mw, event (optional), available_pct (optional). Without actual data the correction has nothing to learn from.

CSV columns: date, block (1-96), wind_ms (at hub height), density (kg/m³, optional), actual_mw, event (blank, curtailment, outage, maintenance, meter_fail, cutout), available_pct (optional, 0-100). Leave actual_mw blank for the day to forecast. Using Excel? Save as CSV first.

QCA DSM engine (96 blocks)

Pick an SPV, upload schedule and actual generation for one day or many days, set the PPA rate (or a price for each block), the available capacity and your own deviation bands. You get the payable for under-injection and the receivable for over-injection for each block, and totals by day, week, month or quarter. Everything stays in this browser.

Each SPV keeps its own PPA rate, AvC and bands.

How the calculation works and how the files are read

• Per block: Deviation = Actual − Schedule. Negative = under-injection (SPV pays). Positive = over-injection (SPV receives).

• Band limits are % of AvC. With limits of 5% and 10% there are three bands: 0 to 5%, 5 to 10% and above 10%. You can add or remove bands.

• Payable = |deviation| × 250 × price × base %, plus, for each band, the part of the deviation in that band × 250 × price × that band's extra charge %. Receivable = the part of the over-injection in each band × 250 × price × that band's receivable %. The number 250 is kWh per MW in one 15-minute block. The BRD gives no receivable rates, so they start at 100%. Please set them to match your PPA or regulation.

• Price: each block uses its own price if the file has a price column (or you upload a price file). Blocks without a price use the PPA rate.

• Many days: the file needs a date column (YYYY-MM-DD or DD-MM-YYYY, day first) and a block column (1 to 96) or a time column (block 1 = 00:00 to 00:15). Without a date column, every 96 rows count as one day starting from the Run date. Results are shown by day, week (Monday to Sunday), month or financial-year quarter (Q1 = April to June).

• Several SPVs: a column named spv, plant or project groups the rows. The SPV you select is calculated. New names are added to your SPV list.

• Other: headers containing "schedule" and "actual" are found automatically. Without headers, columns 1 to 3 are block, schedule and actual. Empty or non-numeric cells count as 0. Saved runs (one per day) live in this browser only. Use "Download all runs" in Historical logs as a backup.

DSM per block, split by band. Orange stack = under-injection (UI) payable, green stack = over-injection (OI) receivable. Light shades are the lower bands (small deviations), dark shades the upper bands (large deviations).
